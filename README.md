# Localizer-IoT — русификация Windows IoT Enterprise LTSC

Windows Forms-приложение для обслуживания установочных ISO офлайн с помощью DISM и Windows ADK.

## Сборка

Автономный single-file EXE для Windows x64 собирается на GitHub Actions. [Сборки и артефакты](https://github.com/skeidGX/Localizer-IoT/actions).

## Что реализовано

- Новый интерфейс с вкладками «Исходный образ», «Языковые источники», «Параметры», «Журнал и диагностика»: постоянная кнопка сборки, текущий этап, прогресс с процентами, сводка выбранных ISO/источников; журнал можно копировать, сохранять и очищать. Версия интерфейса Alpha 0.9.0.1.

- GUI на русском языке, выбор ISO и поддержка drag-and-drop; сохранение/загрузка профилей с путями источников, режимом обработки и опцией Windows Update.
- Экспорт офлайн-пакета в ZIP: найденные языковые CAB/FOD/WinPE и `sources\\ru-ru` ресурсы из выбранных распакованных папок, с `bundle-manifest.txt` и SHA-256 для каждого элемента; LCU/SSU/KB/MSU исключаются.
- Анализ `install.wim` / `install.esd`, индексов, имени редакции, версии и архитектуры через DISM.
- Отдельные источники для Language Pack ISO, Features on Demand ISO/папки и русских Setup-ресурсов `sources\\ru-ru`.
- Отдельный источник «Русский ISO-донор»: программа проверяет редакцию/версию/архитектуру первого индекса, ищет в ISO самостоятельные CAB-пакеты ru-RU, языковые FOD/WinPE и `sources\\ru-ru`. Донор не изменяется; он используется только как источник найденных ресурсов.
- Автоматический поиск и загрузка совместимого русского Language Pack через UUP Dump JSON API с проверкой размера и SHA-1; до трёх параллельных загрузок, прогресс по переданным байтам, повторные попытки с backoff, обновление истёкших ссылок и продолжение `.partial` загрузок по HTTP Range, если сервер поддерживает Range. Подтверждённые файлы повторно используются из локального кеша; манифесты кеша содержат SHA-256 и позволяют проверить локальные CAB и использовать подходящий кеш при недоступности UUP Dump. Языковые обновления ОС (LCU/SSU/KB/MSU) отсекаются; language ESD преобразуются в CAB. Если источник не удалось однозначно подобрать, можно указать CAB/ISO вручную.
- Автоподбор по базовой линии Windows: 19041 для семейства Windows 10 2004–22H2, 22621 для Windows 11 22H2/23H2 и 26100 для Windows 11 24H2 / IoT Enterprise LTSC 2024. Для базы 26100 добавлены резервные источники UUP Dump на случай пустого результата поиска; UUP Dump всё равно может не содержать нужный выпуск или компоненты для конкретной архитектуры.
- По умолчанию обрабатываются все индексы `install.wim`; можно выбрать один. `install.esd` экспортируется во временный WIM, исходный ISO не изменяется.
- Проверка версии и архитектуры основного языкового CAB до внедрения. Проверка учитывает известные общие servicing baselines: например, пакет Language Pack/FOD с базой 19041.1 применяется в семействе Windows 10 2004–22H2 (в том числе OS build 19044 для LTSC 2021), а база 22621 используется семейством Windows 11 22H2/23H2; для Windows 11 24H2 / IoT Enterprise LTSC 2024 используется база 26100. Название редакции (Enterprise vs IoT Enterprise) само по себе не является основанием для отказа: Microsoft описывает IoT Enterprise как binary equivalent Windows Enterprise. CAB, похожие на LCU/SSU/KB или MSU, не применяются — обновлять Windows программа не должна.
- Внедрение русского Language Pack; попытка установки Language Features on Demand (Basic, Fonts, OCR, Speech, Text-to-Speech, Handwriting), когда есть совместимые источники. Дополнительный флажок может разрешить Windows Update только для недостающих языковых FOD-возможностей — по умолчанию выключен, и он не разрешает установку накопительных обновлений ОС.
- Настройки ru-RU для языка интерфейса, системной и пользовательской локали, русской клавиатуры по умолчанию и английской дополнительной, часового пояса и `UILanguageFallback=en-US`.
- Обработка `boot.wim` и встроенного `winre.wim` только при наличии пакетов, совместимых с их базовой сборкой и архитектурой; несовместимый WinPE-пакет не должен внедряться молча.
- Создание `autounattend.xml`, если его ещё нет. Существующий файл сохраняется, потому что он может содержать настройки владельца.
- Генерация `lang.ini`, отдельный загрузочный ISO, журнал и отчёт `.report.txt`; отчёт фиксирует, что обновления ОС не интегрировались и отмечает выбранный режим получения языковых FOD. Предыдущий выходной файл остаётся нетронутым до успешного создания нового ISO.
- Перед сборкой проверяется наличие `oscdimg.exe` и совместимых WinPE language components для `boot.wim`. При необходимости программа может предложить скачать с серверов Microsoft установщики ADK и matching WinPE add-on, проверить Authenticode-подписи и установить соответствующие инструменты.


Профили JSON сохраняют только выбранные пути/параметры; загрузка профиля не запускает обработку автоматически. Экспорт ZIP сканирует только папки, которые уже распакованы или являются локальным кешем; он не распаковывает ISO автоматически. Манифест кеша — локальная проверка целостности, а не замена проверке цифровой подписи издателя.

WinRE обслуживается отдельно: программа ищет `lp.cab` и соответствующие `_ru-ru.cab` только в language media, отличном от установленного ADK, и добавляет языковые пакеты только для WinPE optional components, которые уже присутствуют в WinRE. Если подходящего источника нет, программа оставляет WinRE без изменений и добавляет предупреждение в отчёт.

## Скорость загрузки и отмена

Загрузчик использует параллелизм до трёх файлов, ограниченные повторные попытки при временных HTTP-ошибках и локальный кеш. Если загрузка оборвалась, файл `.partial` может быть продолжен с помощью HTTP Range; если сервер не поддерживает продолжение, файл скачивается заново. Кнопка «Отменить загрузку» отменяет поиск/загрузку языковых файлов, но не прерывает уже запущенную операцию обслуживания DISM.

## Использование русского ISO-донора

1. Выберите исходный English Windows IoT Enterprise LTSC ISO в поле «Исходный ISO».
2. В поле «Русский ISO-донор» укажите совместимый русский Windows 11 ISO или папку с его распакованным содержимым.
3. Нажмите «Проверить донор». В журнале смотрите версию/архитектуру, число самостоятельных Language Pack CAB, языковых FOD/WinPE CAB и наличие `sources\\ru-ru`.
4. Запустите создание ISO. Если донор содержит подходящий основной Language Pack CAB, программа использует его; Setup/FOD/WinPE ресурсы будут использованы только если они присутствуют и проходят проверки совместимости.

Если проверка пишет, что отдельный основной Language Pack CAB не найден, это не ошибка сканирования: русский язык может быть уже встроен в `install.wim`, но не поставляться на медиа как самостоятельный CAB. В таком случае требуется официальный совместимый Language Pack ISO/папка/CAB или доступный источник UUP. Программа не создаёт суррогатные CAB из файлов установленной Windows.

## Что пока требует пользователя и тестирования

- **Автоскачивание — best effort, не гарантия полной локализации.** Программа ищет базовую версию в UUP Dump API и скачивает подходящие Language Pack и языковые функции, если соответствующие файлы доступны. UUP Dump — сторонний каталог метаданных; сами пакеты скачиваются по HTTPS с хостов Microsoft и сверяются с хешем из API. Нужный старый выпуск или FOD-компонент может отсутствовать, а пакет, подготовленный для базовой ветки, всё равно должен пройти проверку DISM на целевом образе.
- Если автоматический поиск не нашёл основной CAB или нужные FOD, их можно указать вручную либо проверить отдельное поле «Русский ISO-донор». Русский установочный ISO может содержать уже локализованный `install.wim`, но не самостоятельный Language Pack CAB; в таком случае программа не извлекает/не пересобирает CAB из установленного хранилища компонентов и потребует исходный совместимый пакет. Для подходящего выпуска можно использовать клиентский Language Pack от обычной Windows Enterprise, если совпадают совместимая базовая версия и архитектура; название редакции «IoT» само по себе не должно блокировать пакет.
- Для полной русификации Setup нужны `lp.cab`, WinPE-Setup CAB-компоненты именно подходящей версии и файлы `sources\\ru-ru`. Если они отсутствуют или несовместимы, приложение добавит предупреждения в отчёт; отдельные экраны могут остаться на английском.
- Автоматическая загрузка не предоставляет гарантированного полного репозитория Features on Demand для всех выпусков. Для некоторых версий FOD ISO/репозиторий потребуется указать вручную. Подбор ADK/WinPE add-on автоматизирован для Windows 10 LTSC 2019/2021 и Windows 11 22H2/23H2/24H2+ известных servicing baseline; неподдерживаемые версии требуют ручного источника. `sources\\ru-ru` setup-ресурсы всё ещё нужно получить из совместимого Russian Windows media, если их нет в исходном ISO.
- Сборка EXE проверена GitHub Actions, но end-to-end проверка не завершена: нужен реальный Windows IoT Enterprise LTSC ISO и тестирование полученного ISO в виртуальной машине. Успешная компиляция не доказывает, что итоговый носитель загрузится на конкретном устройстве.

## Требования

- Windows 10/11 x64 как рабочая станция обслуживания.
- Права администратора (запуск приложения запрашивает их).
- Language Pack CAB `ru-RU` для целевой редакции, версии и архитектуры.
- Совместимый Languages and Optional Features/FOD источник.
- Для полной локализации Windows Setup — совпадающие WinPE language optional components и файлы `sources\\ru-ru`. При согласии программа может загрузить/установить совместимый ADK/WinPE add-on; если нужный выпуск не покрыт автоподбором или установка не удалась, потребуется ручной источник.
- Интернет нужен для автоматического поиска/загрузки через UUP Dump и при необходимости для bootstrapper ADK. Отсутствующие FOD и Setup/WinPE компоненты могут потребовать отдельные медиа.

## Безопасность

Исходный ISO не изменяется: работа идёт в отдельной временной папке, а конечный ISO заменяет выбранный выходной файл только после успешного построения. Сначала тестируйте результат в виртуальной машине, затем на целевом устройстве.
